# Windows hotfix investigation

The investigation started from main `6f5b82bf3` with the Russian text choices from #551. The reported Windows build is `d01e850`, running Restoration Project 2.4.34. All game tests used disposable copies.

| Report | Reproduction and result |
| --- | --- |
| 1. Region capture | In Temple entrance combat, Enter and Space went through the combat loop before the mark handler. The candidate puts the active mark first, shows the new Ctrl+F12 and Esc prompt, and guards against F12 repeat. The mark stayed active through a 1.8 second hold in both instrumented SDL tests. Release and a new press wrote exactly one set of files. In the combat fixture, Space left the mark active, Esc cancelled it, and a separate Enter run saved without ending combat. Combat, player turn and 9 AP persisted. On the copied `ARCAVES.SAV` e0 at hero 20467, camera 18679, zoom 1.28 and 3440x1440 at 2x, an injected logical rectangle `[1366,223,198,166]` put the PNG outline at physical x 2732 to 3128 and y 446 to 778. JSON included pot PID 243 at tile 19864. The +15 degree test also included the pot. [Rectangle comparison](region-alignment.jpg). Native mouse drag in the packaged build remains open. |
| 2. Cursor trails | The original `f2r-feedabck.mp4` shows two yellow arrows at 00:15 with 1 FPS and 928.8 ms. Sampled images are nearly static after the opening second. The test opened inventory and delivered scripted motion, but the captured frames did not establish cursor movement or reproduce the duplicate. The stale patch in the sharp-text overlay cache remains a lead. The stall is a separate report. |
| 3. Silhouette outlines | The projected object outline pass is separate from the mouse sprite. Ordinary ARCAVES combat captures show that pass, but the exact reported malformed outline was not isolated, and the turned targeting fixture timed out. |
| 4. Pot depth | The e0 object at tile 19864 is PID 243, art `arvase1.frm`. The exported upper rim has a positive support height, which both rest-card mesh paths discarded. Applying the height fixed the ordinary view and produced a crossed rim at +15 degrees. The trial was reverted. Correct geometry at both angles and a second object remain open. |
| 5. Camera travel | On copied `ARCAVES.SAV` e2 with hero 21125, center 22307 and zoom 1.28, the background wide viewport moved left to EDG limit 19930. The candidate moved that stop to 18743. It added 416 logical pixels left and right, 144 up, and 224 left at 960x540 logical size. The existing lower floor limit was 120 pixels below the authored stop. The candidate reached 144 below it, 24 past the prior effective stop. Corner tests reached stable stops. The camera moved back from the extended edge after zoom-in and after a switch to 2D. [Camera comparison](camera-left.jpg). The owner's borderless stop at 22307, the door click and world-map behavior remain open. |
| 6. Fullscreen fades | Russian inventory and character editor entry and exit showed the local 3D background and no lingering black layer in the sampled frames. The capture rate was too low to rule out a one-frame flash or measure fade duration. Pip-Boy entry was captured with the stock fixture. Pip-Boy exit and dialogue remain open. |
| 7. Local 3D | The ordinary Temple combat fixture stayed at `scene-gl/full` with the same camera center through the end of combat. Walk probes verified ARCAVES to ARTEMPLE and ARVILLAG to ARTEMPLE independently. Arrivals stayed in 3D after the loading screen. ARTEMPLE to ARVILLAG reached 3D without a logged exit click, so the route is unverified. The complete return and the exit after combat remain open. |

The branch is a draft. The two proposed changes cover region capture and camera travel. The other reports are still open.
